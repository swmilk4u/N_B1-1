어려운 개념 대신, '코드용 클라우드', '개발자들의 협업 놀이터'와 같이 쉬운 비유로 설명하기

2. 핵심 개념 콕콕! GitHub 용어와 친해지기
Repository (리포지토리)
'프로젝트를 담는 하나의 폴더' 또는 '보관함'이라고 생각하면 쉬워요.
Commit (커밋)
'의미 있는 변경 사항을 하나의 단위로 묶어 저장하는 것'이에요. 게임의 '세이브 포인트'와 비슷해요.
Push (푸시)
내 컴퓨터(로컬)에서 작업하고 커밋한 내용을 GitHub(원격)에 '업로드'하는 과정이에요.
Branch (브랜치)
'독립적인 작업 공간을 만드는 것'이에요. 원본에 영향을 주지 않고 새로운 기능을 시험해볼 수 있는 '복사본' 같은 개념이에요.
Pull Request (PR, 풀 리퀘스트)
내가 브랜치에서 작업한 내용을 "원본에 합쳐주세요!"라고 정식으로 '요청'하는 기능이에요.
3. 내 첫 번째 저장소 만들기 (Repository 생성)
Step 1: GitHub 로그인 후 'New' 버튼 클릭하기
스크린샷과 함께 버튼 위치를 친절하게 안내하기

Step 3: 필수 옵션 체크하기

Step 4: 'Create repository' 클릭!
"축하합니다! 여러분의 첫 번째 코드 저장소가 만들어졌어요!" 와 같은 격려 메시지 포함하기
4. 내 코드를 저장하고 공유하기 (Commit & Push)

Step 2: 간단한 파일 수정 또는 추가하기
README.md 파일을 열어 자기소개를 추가하는 예시 보여주기
Step 3: 변경사항 기록하고 업로드하기
git add: 변경된 파일을 '장바구니'에 담는 과정
git commit: 장바구니에 담은 물건에 '이름표'를 붙여 저장하는 과정
git push: 저장한 내용을 GitHub 서버로 '배송'하는 과정
각 단계의 역할을 비유를 들어 쉽게 설명하기
5. 안전하게 작업하는 방법 (Branch)
왜 브랜치가 필요할까요?
'main' 브랜치는 언제나 안정적으로 실행되는 '최종본'으로 두고, 새로운 작업은 별도의 공간에서 안전하게 해야 함을 설명하기
새로운 브랜치 만들기

브랜치에서 작업하기
새로운 브랜치에서 파일을 수정하고, 위에서 배운 commit & push 해보기
6. 내 작업을 합쳐달라고 요청하기 (Pull Request)
Step 1: GitHub에서 Pull Request 버튼 누르기

내가 어떤 작업을 왜 했는지 제목과 내용을 작성하는 것의 중요성 설명하기
Step 3: Pull Request 생성 및 병합(Merge)
PR을 생성하고, 직접 자신의 PR을 'Merge'하며 작업을 원본(main)에 합치는 경험 해보기

2. 이것만 알면 돼요! GitHub 필수 단어 5가지
Repository (리포지토리): 그냥 **'프로젝트 폴더'**라고 생각하세요. 내 모든 코드와 파일이 담기는 곳이에요.
Commit (커밋): 게임의 '세이브(저장)' 기능이에요. "여기까지 작업했음!" 하고 깃발을 꽂는 거죠.
Push (푸시): 내 컴퓨터에서 작업하고 '저장(커밋)'한 내용을 GitHub 사이트로 **'업로드'**하는 거예요.
Branch (브랜치): '복사본 만들기' 기능이에요. 원본은 그대로 두고, 복사본에서 새로운 기능을 마음껏 실험해볼 수 있어요.
Pull Request (풀 리퀘스트): 복사본에서 작업한 게 마음에 들면, "제가 만든 이 기능, 원본에 합쳐주세요!" 하고 **'검토 요청'**을 보내는 거예요.
3. 내 첫 온라인 코드 폴더 만들기 (Repository 생성)
1단계: GitHub에 로그인해서 오른쪽 위에 있는 + 버튼 누르고 New repository를 클릭해요.
2단계: 폴더 이름(Repository name)을 정하고, 어떤 프로젝트인지 간단한 설명(Description)을 적어주세요.
3단계: Add a README file 이라는 네모 박스를 꼭! 체크해주세요. 이게 우리 프로젝트의 '대문' 역할을 해요.
4단계: 초록색 Create repository 버튼을 누르면 끝!

2단계: 파일 수정하기

3. 저장하고 업로드하기 (가장 중요해요!)
add: "나 이 파일 바꿨어!" 라고 컴퓨터에게 알려줘요. (장바구니에 담기)
commit: "이렇게 바꿨어!" 라고 메모를 남기며 저장해요. (내용물 포장하고 이름표 붙이기)
push: 저장한 내용을 GitHub 사이트로 업로드해요. (택배 보내기)
5. 원본은 소중하니까! 복사본에서 작업하기 (Branch)
왜 필요할까요?
중요한 원본 파일을 실수로 망가뜨리면 안 되잖아요. 그래서 항상 안전하게 복사본을 만들어서 거기서 작업하는 거예요.
어떻게 만드나요?
my-first-edit 처럼 내가 알아보기 쉬운 이름으로 새로운 복사본(브랜치)을 만들어요.
6. "제가 작업한 것 좀 봐주세요!" (Pull Request)
1단계: 복사본에서 열심히 작업한 내용을 GitHub에 push(업로드)해요.
2단계: GitHub 사이트에 들어가면 "이거 원본에 합칠래?" 하고 초록색 버튼이 보일 거예요. 그걸 눌러주세요.
3단계: 내가 뭘 바꿨는지 간단히 제목과 설명을 쓰고, **'검토 요청(Pull Request)'**을 보내면 끝!
이제 다른 사람들이 내 코드를 보고 의견을 줄 수도 있고, "좋아요!" 하면서 원본에 합쳐줄 수도 있답니다.

결론: 이렇게 GitHub를 쓰면 여러 사람이 동시에 작업해도 코드가 꼬이지 않고, 서로의 작업을 투명하게 확인하며 더 좋은 결과물을 만들 수 있어요.

1. GitHub와 첫 만남, 어렵지 않아요!
학습 목표: "아, 이래서 GitHub를 쓰는구나!" 하고 무릎을 탁! 칠 수 있어요.
내용:
코딩하다가 밤새 만든 파일이 날아가서 울어본 적 있나요? 실수로 잘못 고쳐서 이전 버전으로 되돌리고 싶었던 적은요?
걱정 마세요! GitHub는 **'코드를 위한 타임머신 기능이 있는 구글 드라이브'**라고 생각하면 딱 맞아요.
내 소중한 코드를 안전하게 온라인에 보관해주고, 원할 땐 언제든 과거의 특정 시점으로 코드를 되돌릴 수 있답니다. 정말 신기하죠?
2. 딱 5개만! GitHub 필수 단어 완전 정복
학습 목표: 어려운 용어 대신, 재미있는 비유로 GitHub 핵심 기능을 이해할 수 있어요.
내용:
온라인 코드 폴더 (Repository): 내 모든 코드를 담아두는 온라인 비밀 상자예요.
변경 내용 저장 (Commit): 게임에서 '저장!' 버튼 누르는 것과 똑같아요. "여기까지 완료!" 하고 깃발을 꽂는 느낌이죠.
온라인에 올리기 (Push): 내 컴퓨터에서 꽂은 깃발(저장 내용)을 온라인 비밀 상자로 택배 보내기라고 생각하면 쉬워요.
안전한 복사본 만들기 (Branch): 마법 복제 종이 같아요. 원본은 그대로 두고, 복제 종이에 마음껏 새로운 기능을 그리거나 실험해도 원본은 절대 망가지지 않아요!
코드 검토 요청 (Pull Request): "제가 복제 종이에 그린 그림인데, 원본에 합쳐도 될까요?" 라고 팀장님께 정중하게 물어보는 쪽지예요.
3. 내 첫 온라인 비밀 상자 만들기
학습 목표: 마우스 클릭 몇 번으로 나만의 첫 온라인 코드 공간을 만들 수 있어요.
핵심 따라하기: hello-world 라는 이름으로 내 첫 온라인 비밀 상자를 만들어 봐요!
단계별 설명:
GitHub 로그인 후, 오른쪽 위 + 버튼을 누르고 New repository를 살포시 눌러주세요.
이름(Repository name) 칸에 hello-world 라고 적어주세요.
Add a README file 네모 박스를 꼭! 체크해주세요. (나중에 아주 편해져요!)
초록색 Create repository 버튼을 누르면…
짜잔! 여러분만의 소중한 코드 공간이 탄생했어요! 정말 멋져요!
4. 내 컴퓨터에서 온라인으로! 코드 택배 보내기
학습 목표: 내 컴퓨터에서 작업한 내용을 3단계에 걸쳐 안전하게 온라인으로 보낼 수 있어요.
핵심 따라하기: README 파일에 내 소개를 한 줄 추가하고, 온라인에 택배를 보내봐요!
택배 보내는 3단계:
물건 담기 (add): "나 이 파일 바꿨어!" 하고 컴퓨터에게 알려주는 단계예요. (택배 상자에 물건을 담는 것과 같아요.)
송장 붙이기 (commit): "자기소개 추가함" 처럼, 왜 바꿨는지 메모를 남겨 저장해요. (상자에 '내 소개 파일'이라고 송장을 붙이는 거죠.)
택배 발송! (push): 저장한 내용을 진짜 온라인 비밀 상자로 슝~ 하고 보내면 끝!
5. 원본은 소중해요! 마법 복제 종이 사용법
학습 목표: 원본 코드를 절대 망가뜨리지 않는 안전한 작업 습관을 익힐 수 있어요.
핵심 따라하기: my-idea 라는 이름으로 나만의 마법 복제 종이를 만들어 봐요.
내용:
프로젝트의 원본(main)은 언제나 잘 돌아가는 상태여야 해요.
그래서 새로운 기능을 추가하거나 무언가 고칠 땐, 꼭! 복제 종이를 만들어 그 위에서 마음껏 실험하는 거예요.
실수해도 괜찮아요! 우리는 안전한 복제 종이 위에서 작업할 거니까요.
6. "제가 한 작업, 한번 봐주실래요?" (코드 검토 요청 쪽지 보내기)
학습 목표: 내가 복제 종이에서 작업한 내용을 원본에 합쳐달라고 정식으로 요청할 수 있어요.
핵심 따라하기: my-idea 복제 종이에서 작업한 내용을 원본(main)에 합쳐달라고 요청 쪽지를 보내봐요.
단계별 설명:
복제 종이에서 작업한 내용을 '온라인에 택배 보내기(Push)' 해요.
GitHub 사이트에 들어가면 "너 혹시 합치기 요청할래?" 라는 느낌의 초록 버튼이 반짝이고 있을 거예요. 그걸 눌러주세요.
"이런 기능을 만들었어요!" 라고 예쁘게 제목과 설명을 적고 코드 검토 요청 쪽지를 보내면 완료!
7. 진짜처럼! 철수와 영희의 팀 프로젝트 엿보기
학습 목표: 여러 사람이 GitHub로 어떻게 멋지게 협업하는지 구경하며 자신감을 얻어요.
상황: 철수와 영희가 함께 쇼핑몰 사이트를 만들기로 했어요!
비밀 상자 공유: 팀장 철수가 shopping-mall 온라인 비밀 상자를 만들고 영희를 초대해요.
역할 분담: 철수는 '로그인 페이지', 영희는 '상품 목록 페이지'를 만들기로 해요.
각자 복제하기: 철수는 login-page, 영희는 item-list 라는 이름의 마법 복제 종이를 각자 만들어서 작업 시작! (서로 간섭할 일이 없겠죠?)
쪽지 보내기: 영희가 먼저 작업을 끝내고, "상품 목록 페이지 완성! 코드 한번 봐줘~" 라며 철수에게 코드 검토 요청 쪽지를 보내요.
칭찬과 합치기: 철수는 영희의 코드를 보고 "와, 진짜 잘했다!" 칭찬 댓글을 남기고, 승인 버튼을 눌러 원본에 합쳐줘요. 철수도 같은 방식으로 진행한답니다.
결론: 어때요? 이렇게 하니 여러 명이 함께 일해도 코드가 엉킬 걱정이 전혀 없겠죠?
8. 축하합니다! 이제 여러분도 GitHub 능력자!
